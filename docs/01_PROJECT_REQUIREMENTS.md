## 一、系统定位

面向大学生的 AI 驱动职业规划 Web 应用，提供 **简历上传 → 学生画像 → 人岗匹配 → 路径规划 → 报告导出** 五步闭环。

核心价值主张：**结构化画像 + 可解释评分 + 路径图谱 + 可执行行动计划**。

系统分为两个前端：
- **管理端（Admin Desktop）**：数据管理、岗位画像生成、系统监控
- **学生端（Student Mobile）**：简历上传、画像查看、匹配探索、报告生成

### 3.2 准确性要求（赛题硬性指标）

| 指标 | 目标值 |
|------|--------|
| 人岗匹配关键技能匹配准确率 | ≥ 80% |
| 岗位画像关键信息准确率 | ≥ 90% |
| 学生画像关键信息准确率 | ≥ 90% |

### 3.3 AI 调用规范

| 规范 | 说明 |
|------|------|
| 结构化输出 | 所有 AI 生成结构化数据必须使用 `structured_output` + JSON Schema 校验 |
| 推理链控制 | 延迟敏感任务（简历解析/软技能评估）设置 `disable_reasoning=True` |
| 模型配置 | 开发环境: StepFun Step-3.5-Flash via OpenRouter；生产环境: 官方 StepFun URL |
| 请求头 | OpenRouter 必须设置 `HTTP-Referer` + `X-Title` header |
| 向量嵌入 | Alibaba Cloud DashScope `text-embedding-v4`（1024维） |

## 四、数据说明

### 4.1 JD 数据集

- 来源：企业提供（计算机类信息化相关行业）
- 数据量：~9,958 条 JD，覆盖 51 种岗位角色
- 存储：PostgreSQL `jobs` 表（~9,178 条已入库）
- 字段：职位名称、工作地址、薪资范围、公司全称、所属行业、人员规模、企业性质、职位编码、职位描述、公司简介
- 文件格式：`.xls`（需 `xlrd` 库读取，非 `openpyxl`）

### 4.2 岗位画像数据

- 存储：PostgreSQL `job_profiles` 表（当前 23 条）
- Dashboard 中「已入库岗位」映射到 `jobs` 表（~9,178），非 `job_profiles`

### 4.3 PostgreSQL 特殊处理

- 数组字段序列化为 `{value1,value2}` 格式字符串，前端需解析
- 向量索引：pgvector 扩展

## 六、已知约束与注意事项

1. **uvicorn 热重载限制**：新增 `.py` 文件后必须手动重启，热重载仅对已加载模块的修改生效
2. **Vite 代理 SSE 缓冲**：需专用代理规则 `selfHandleResponse: false`
3. **Schema 不匹配是高频 bug 来源**：前后端字段名/嵌套结构必须两端对照验证
4. **Windows + WSL2 环境**：PowerShell 不支持 `&&` 链式命令；跨环境进程管理可能冲突
5. **无硬编码默认值**：URL/API Key/模型名称全部走 `.env` 配置
